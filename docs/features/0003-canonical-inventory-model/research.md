Key decisions from distributor research:

- Dropshipping is out of scope for the MVP. `CANDROPSHIP` and dropship API endpoints should not determine whether a product can be listed.

- Dealer/API authenticated access may be useful later, but the first adapters should consume dealer-downloaded files.

## Official GoDaddy References

Official GoDaddy pages were downloaded to the parent project folder:

- `../references/godaddy/catalog-import-starter-template-42984.html`
- `../references/godaddy/import-products-from-a-csv-file-16581.html`
- `../references/godaddy/format-my-online-store-product-spreadsheet-16580.html`

Source URLs:

- https://www.godaddy.com/help/catalog-import-starter-template-42984
- https://www.godaddy.com/help/import-products-from-a-csv-file-16581
- https://www.godaddy.com/help/format-my-online-store-product-spreadsheet-16580
- https://www.godaddy.com/help/manage-my-online-store-inventory-12384

Important findings:

- The local template appears to match GoDaddy's catalog import starter template.
- For new product imports, `PRODUCT ID` should be left blank so GoDaddy can autogenerate it.
- `PRODUCT ID` is required when updating existing products.
- `SHORTCODE` is optional and can be autogenerated.
- `TYPE` defaults to `PHYSICAL`.
- `STATUS` supports `ACTIVE`, `DRAFT`, and `ARCHIVED`.
- `ALLOW CUSTOM PRICE` should be `FALSE` if `PRICE` or `SALE PRICE` is filled.
- Websites + Marketing `Price` uses normal currency amounts, not cents. GoDaddy says to use numbers or decimals with up to 2 decimal places, no currency sign, and no thousands comma. Examples include `7`, `7.50`, and `1000`.
- Websites + Marketing CSV import supports only physical products.
- Websites + Marketing Commerce bulk upload is limited to 100 products at a time.
- CSV import supports one image per product during import.
- GoDaddy inventory management supports tracking inventory, quantity on hand, low inventory alerts, and backorder behavior.
- Current research did not find a CSV import field that safely creates an inquiry-only or "call for details" product state.

Important GoDaddy defaults for this project:

- `TYPE`: `PHYSICAL`
- `STATUS`: likely `ACTIVE` for rows selected for export
- `ALLOW CUSTOM PRICE`: `false`
- `TRACK INVENTORY`: `true`
- `ALLOW BACKORDER`: likely `false`
- `DISABLE SHIPPING`: likely `false`
- `FREE SHIPPING`: likely `false`

Resolved assumption: GoDaddy export prices should be formatted as normal currency amounts, not cents. For example, five hundred dollars should be exported as `500` or `500.00`, not `50000`.

Resolved decision: support both new-import and update-import workflows. New import is the default. Update mode requires known GoDaddy `PRODUCT ID` mappings, which should come from a GoDaddy export synced into local SQLite storage.

Ownership decision:

- GoDaddy owns `PRODUCT ID`.
- Inventory Feed Tool owns stable SKUs, source identifiers, and internal matching keys.
- Inventory Feed Tool should not generate or invent GoDaddy `PRODUCT ID` values.
- New-import exports leave `PRODUCT ID` blank.
- Update exports populate `PRODUCT ID` only from known GoDaddy mappings.


If `IMAGENAME` is blank or looks like a default/missing image, leave `image_url` blank and attach a warning.

- Quantity rows not present in inventory: 384
- Missing UPC rows in inventory: 52
- Missing dealer price rows in inventory: 0

- Inventory downloads are available to logged-in dealers from `Resources -> Inventory Download`.

- `Call` means the dealer should contact their Account Executive for quantity availability.

## Cross-Distributor Considerations

The sample data has meaningful UPC overlap between Lipseys and Davidsons. Earlier analysis found 4,172 overlapping UPCs between Lipseys in-stock rows and Davidsons inventory rows.

That means the model should support:

- Stable product identity independent of distributor SKU.
- Source-specific SKU and source-specific cost/quantity.
- Multiple distributor offers for the same product.
- Later duplicate resolution by UPC or another product key.
- Later source selection by profit, availability, distributor priority, or explicit user override.

Duplicate/source selection is not part of this feature, but the model must not make it harder.

## Conflict Scenarios

Expected conflicts when the same UPC appears in multiple feeds:

- Different distributor costs.
- Different available quantities.
- Different MAP values.
- Different sale prices.
- Different descriptions or names.
- One source has images while another does not.
- One source has package dimensions while another does not.
- Conflicting compliance flags, such as one source saying FFL required and another saying it is not.
- One source has stock while another is out of stock.

The model should preserve all source offers and attach conflict messages at the canonical product level. Exporters should use the selected offer for price, quantity, cost, and source-specific fulfillment data.

Default future source-selection policy:

1. Exclude unavailable offers.
2. Exclude offers with blocking validation errors.
3. Prefer the offer with highest estimated gross profit.
4. If tied, prefer higher quantity.
5. If tied, use configured distributor priority.

Estimated gross profit:

```text
selected_export_price - distributor_unit_cost
```

The selected export price should use the configured pricing strategy, including MAP handling. This is only an estimate; a future feature should allow distributor priority and per-product overrides because the most profitable source may not always be the best operational choice.

## Future Storage And Update Workflow

SQLite should be used as the local mapping and run-history store in a future feature.

Planned workflow:

1. User runs a new-import export from distributor feeds.
2. Tool writes GoDaddy CSV batches with blank `PRODUCT ID`.
3. Tool records exported item identity data locally, with unknown GoDaddy product IDs.
4. User imports the generated CSVs into GoDaddy.
5. User exports product data from GoDaddy.
6. User syncs that GoDaddy export into Inventory Feed Tool.
7. Tool matches GoDaddy rows by SKU first, then UPC when needed.
8. Tool stores GoDaddy-assigned `PRODUCT ID` values in SQLite.
9. Future update exports can populate `PRODUCT ID` from SQLite.
10. Tool stores source offers and selected source decisions per export run.
11. Tool stores user overrides such as "always prefer Lipseys for this UPC."

If update mode is selected and mappings are missing, the UI should guide the user to provide a GoDaddy export file before producing an update CSV.

## Additional Early Considerations

Items to keep visible before coding feed adapters and exporters:

- Compliance handling: GoDaddy has no dedicated FFL/SOT/NFA columns, so the first exporter will likely need description notes and later filtering/reporting controls.
- Category handling: GoDaddy's provided template does not expose a category column. Category/family values should still be preserved in the middle model, but storefront category assignment is secondary for the first import.
- Image reliability: Lipseys image URLs appear publicly usable from the image CDN. Missing or broken image URLs should warn only and should not block otherwise valid product rows.
- Inventory freshness: neither distributor treats cart/wishlist state as a reservation. The generated CSV is a snapshot, so the UI should eventually show the feed timestamp and warn users to import promptly.
- Excluded offers: allocated, unknown, and zero-quantity offers should not disappear from internal reports. For the MVP, allocated and unknown-quantity offers should be preserved internally but not exported by default.
- Authenticated retrieval: Davidsons FTP and Lipseys API/feed access should be treated as future dealer-authorized integrations. The MVP should stay file-based.
